`Lynx-webapp` is the **coach & admin dashboard** on the web — a role-gated port of
the Flutter app's **staff** surface, plus web-only features (CRM, Payments,
Notifications). Clients stay on the mobile app; this is for coaches and admins. It
talks to the **same Supabase project** as the Flutter app, so auth and data are
shared.

## Stack

**Turborepo** monorepo (from the `react-vite-shadcn-starter`). **React 19 + Vite +
React Router 7 + TanStack Query + shadcn/ui (Tailwind v4) + Supabase JS.** Hosted on
**Vercel**. Biome lints, Lefthook gates, Vitest + MSW for tests.

A **single app** (`apps/app`) serves both coach and admin — admin is a role-gated
superset, not a separate build. Shared packages: `@lynx/ui` (shadcn primitives +
theme), `@lynx/auth` (Supabase auth adapter), `@lynx/supabase` (typed client + env),
`@lynx/types`.

## Auth, roles & the gate

Auth is shared Supabase (email + password; SSO gated off). The spine is the same:
a signed-in `auth.users` row resolves to a **`users_data`** person and its
**`person_roles`**. A `useCurrentUser` query (the "me") exposes `personId`,
`tenantId`, `roles`, `isStaff`, `isAdmin`. `ProtectedRoute` gates the shell to
**staff** (`owner`/`coach`/`physio`); a non-staff or unlinked account hits a
"coaches only" screen. Admin-only nav (e.g. Payments) is filtered by `isAdmin`. All
queries are tenant-scoped; RLS enforces it server-side.

## Design system

Ported 1:1 from the Flutter theme and driven through semantic tokens so light/dark
flips cleanly: forest `#004225` on cream `#F5F1E8` (light), deep-forest (dark);
Bricolage Grotesque + Inter; elevation-0 cards with a forest-tinted double shadow +
hairline. Theme toggle (light/dark/system, persisted) adds `.dark` to `<html>`.
**i18n:** EN + SL via i18next; a language switcher lives in the top bar.

## Backend types

`npm run db:types` regenerates `packages/supabase/src/database.types.ts` from the
hosted project (`afrqrnipjrnwnwxrfjvx`) — the typed `Database` is threaded through
`createClient<Database>`, so every table and RPC is typed.

## Status

**Phase 0 (foundation) shipped:** scaffold, shared Supabase client + generated
types, auth + staff gate, light/dark tokens, EN/SL i18n, the app shell
(sidebar / mobile drawer, theme + language toggles), and placeholder routes for
every section.

**Phase 1 (coach port) — complete.** **Clients** shipped end to end over the
existing backend (no schema changes): the tenant client list (`users_data` +
`person_roles` where role = `client`, with search and account/lifecycle badges),
the account-less **New client** flow, and the full **client detail hub** — care
team (`list_client_staff` RPC + `client_staff` assign/unassign), health flags
(add/delete), assigned programs (list + `assign_template` + `resync_assignment`
RPCs), completed sessions, and the invite-code flow. **Exercise library** shipped
too: the owner's exercises with public thumbnails, movement/tag filters and
search, plus a full create/edit editor (thumbnail upload, movements, video link,
description, tag create via `ensure_tag`, and the config-driven metric-schema
editor). The **program builder** is complete: the template list (create / duplicate via
`duplicate_program` / delete), the program editor (name/description + phases →
sessions management with reorder and `duplicate_phase` / `duplicate_session`),
and the full **session editor** — a method-first add flow over the 16 training
methods, the exercise picker, and a prescription editor (strength grid, interval
for EMOM-family, schema fields for method=none, week tag, coach note) with
method groups (superset / contrast / …), edit, remove and reorder. **Groups**
(rosters + group-assign via `assign_template_to_group`), **Review**
(completed-session feed → logged actuals → likes & comments), and **Chat**
(realtime 1:1 via `get_or_create_conversation` + a `postgres_changes`
subscription) are done too, and a read-only **Bookings** schedule (this week's
booked slots over the `bookings` table) rounds out the coach shell. That
completes the coach-app port — the whole Flutter staff surface now runs on the
web.

**Next — Phase 2+ (greenfield):** the append-only **event log**, the **CRM**
boards, **Payments** (Pantheon), and admin/stats. These add new backend
migrations in `Lynx-backend`, not just UI.
