title: Navigation & Shells
description: The go_router setup, the auth redirect gate, and the role-resolved client/staff shells.
---

Navigation is **go_router** with an auth-driven redirect. Routing is deliberately
flat: auth routes, one `/app` entry that resolves the shell, and `/settings`.

## Routes

| Path | Screen |
| --- | --- |
| `/splash` | resolves to `/welcome` or `/app` |
| `/welcome` | landing — brand mark + Create account / Log in |
| `/login` | email + password sign-in |
| `/signup` | email + password sign-up |
| `/verify-email?email=` | 6-digit OTP to confirm a new sign-up |
| `/forgot-password` | request a password-reset code |
| `/reset-password?email=` | enter reset code + choose a new password |
| `/app` | **`RootShell`** — resolves role/tenant, shows the right shell |
| `/settings` → `/settings/change-password` | settings |

All auth routes are **public**. See [Authentication](/docs/features/authentication)
for the full flow.

## The redirect gate

`refreshListenable` is an auth-state notifier, so go_router re-evaluates on every
auth change:

- Password recovery takes precedence — verifying the reset OTP emits
  `passwordRecovery`, which latches `isRecovering` and pins the user to
  `/reset-password` until the new password is set (returning `null` so the
  `?email=` query param is preserved).
- Unauthenticated + non-public route → `/welcome`.
- Authenticated + on a public auth route → `/splash` to resolve.

## RootShell: role → shell

`/app` renders `RootShell`, which resolves the signed-in user's linked person /
tenant / role and shows one of:

- **Finish-setup** — authenticated but **not yet linked** to a person (e.g. a fresh
  signup redeeming an [invite](/docs/features/clients-and-invites)). Until linked,
  RLS returns nothing.
- **Client shell** — Train · Progress/history · [Settings](/docs/features/settings).
- **Staff shell** — Clients · Library (Exercises + Programs) · Review · Groups ·
  [Settings](/docs/features/settings).

Tabs live **inside** each shell (adaptive native Cupertino tab bar / Material
pill), not as separate go_router paths. The client [daily loop](/docs/features/daily-loop)
is the Train tab.

<Callout>
Auth is **password-based with no deep links** in v1 — email verification and
password reset both use numeric OTP codes. Deep-link configs remain in
`core/config/deeplink_config.dart` only for the (gated-off) SSO callback.
</Callout>
