Checkpoint **CP1** (+ **CP6** expansion) · App: `features/exercises` · Backend
migrations: `exercises`, `exercise_movement_metrics`.

Each coach builds **their own** library (full CRUD). Every exercise has a custom
name, a **required thumbnail** (cover image), a **required movement
classification**, a **config-driven logging schema**, a **video** (hosted **or**
linked), a description, and **tags** — tags + movement drive search/filter and the
tag-driven "swap exercise" in the [daily loop](/docs/features/daily-loop).

The library screen offers a **list/grid toggle** (persisted per screen). Grid is a
responsive card grid (thumbnail · name · movement/tags); list is a compact row
layout. Both are searchable and faceted by tag **and movement**.

## Movement (required)

`exercises.movements` is a required (app-enforced ≥1), multi-valued classification
over the enum `movement_type`: **Strength, Hypertrophy, Power, Plyometric, Cardio,
Mobility, Rehab, Warm-up**. Coach-visible only; GIN-indexed; drives the library
filter facet. The column defaults to empty in DB (legacy rows), so the editor
requires the coach to pick ≥1 on next save.

## Config-driven logging metrics

`exercises.metric_schema` (jsonb) is a per-exercise list of logging fields, so the
library covers **any** exercise — running logs pace/time/incline, bench logs
reps/weight, etc. Each field:

```json
{ "key": "pace", "label": "Pace", "type": "decimal", "unit": "min/km" }
```

`type` ∈ `number | decimal | duration | text | enum`; `unit` is free text. A
legacy optional `enumKind` (`rm | rpe | rir`) adds intensity-unit semantics —
the editor **no longer offers** the RM/RPE/RIR intensity chooser when creating
or editing a field (intensity lives in the prescription, not the exercise);
existing fields keep their stored tag and it still renders as the input suffix
in the runner. The client
runner renders this schema dynamically; logged actuals land in
`logged_entries.data` (jsonb, keyed by field key). An empty schema falls back to
the legacy reps/weight inputs. The schema is snapshotted onto
`assignment_exercises.metric_schema` so the client loop (which can't read
`exercises`) can render the form.

## Thumbnail (required)

- Stored as `thumbnail_storage_path` in the **public** Supabase Storage bucket
  `exercise-thumbnails` (path `{tenant_id}/{file}`; staff-only upload via storage
  RLS, public read). A public bucket lets the grid render many covers via **direct
  CDN URLs** (`getPublicUrl`) — fast and cacheable — instead of signing each one.
- The editor **requires** a thumbnail: Save stays disabled until one is uploaded.
  The column is nullable at the DB level so **legacy** exercises created before
  this requirement still load; those render a neutral placeholder in the grid.

## Video: hosted or linked

- **Hosted** (`video_storage_path`) — the coach uploads a clip to a **private
  Supabase Storage bucket** `exercise-videos` (path `{tenant_id}/{file}`; staff-only
  upload, tenant-member read via storage RLS). It streams **inline** in-app via a
  short-lived **signed URL**.
- **Linked** (`video_url`) — an external URL (YouTube/Vimeo) opened in the browser.
- The daily loop reads the snapshot (`assignment_exercises.video_storage_path` /
  `video_url`), so hosted video plays inline in the session runner too.

## Data

<Callout>Tables: `exercises`, `tags`, `exercise_tags` (join). All carry `tenant_id`.</Callout>

**`exercises`**

| Column | Notes |
| --- | --- |
| `id` | uuid pk |
| `tenant_id` | tenant isolation |
| `owner_id` | the coach (person) who owns it |
| `name` | required |
| `description` | optional |
| `video_url` | link-based (v1 default) |
| `video_storage_path` | hosted video (private `exercise-videos` bucket) |
| `thumbnail_storage_path` | cover image (public `exercise-thumbnails` bucket); required by the app, nullable in DB for legacy rows |
| `movements` | `movement_type[]`; required (≥1) classification, coach-visible |
| `metric_schema` | jsonb; config-driven logging fields |

**`tags`** are faceted by `category` (movement pattern · main muscle group ·
equipment · tempo, extensible), unique per `(tenant_id, category, label)`.
`exercise_tags` joins exercises ↔ tags.

## RLS

Tenant isolation is the first predicate on every policy. Within a tenant:

- **Read** — any staff member reads the whole tenant library.
- **Insert** — a new exercise is always owned by its creator (`owner_id = self`).
- **Update / delete** — the **creator** (`owner_id = self`) **or** the tenant
  **`owner`** role (`current_has_role('owner')`). So a coach manages only their
  own exercises, while the tenant owner can edit or delete **any** exercise. The
  `exercise_tags` write policy carries the same creator-or-owner rule so "edit any
  exercise" also covers its tag links.

See [Security & RLS](/docs/backend/security-and-rls).

## App

- `ExerciseRepository` (repository pattern; explicit column selects). Adds
  `uploadThumbnail` and `thumbnailPublicUrl` alongside the video helpers.
- `exercisesProvider` (per-coach), `exerciseTagsProvider`.
- Library screen: searchable / tag- & movement-filterable, **list/grid toggle**
  (`viewModeProvider('exercises')`), with a loading skeleton. Reached as a pushed
  page from the **Programs** tab's "All exercises" action (`ExerciseLibraryScreen(pushed: true)`).
- Editor: **required thumbnail picker**, **required movement multi-select**, a
  **logging-fields (metric schema) builder**, video field, description, tag chip
  editor with **find-or-create** tags; delete. Video opens via `url_launcher`.
