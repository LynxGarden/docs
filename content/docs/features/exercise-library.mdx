Checkpoint **CP1** · App: `features/exercises` · Backend migration: `exercises`.

Each coach builds **their own** library (full CRUD). Every exercise has a custom
name, a **required thumbnail** (cover image), a **video** (hosted **or** linked),
a description, and **tags** — the tags drive search and the tag-driven "swap
exercise" in the [daily loop](/docs/features/daily-loop).

The library screen is a **2-column card grid**: each card shows the thumbnail,
the name, and the exercise's tags, with a small play badge overlaid on the image
when the exercise has a video.

## Thumbnail (required)

- Stored as `thumbnail_storage_path` in the **public** Supabase Storage bucket
  `exercise-thumbnails` (path `{tenant_id}/{file}`; staff-only upload via storage
  RLS, public read). A public bucket lets the grid render many covers via **direct
  CDN URLs** (`getPublicUrl`) — fast and cacheable — instead of signing each one.
- The editor **requires** a thumbnail: Save stays disabled until one is uploaded.
  The column is nullable at the DB level so **legacy** exercises created before
  this requirement still load; those render a neutral placeholder in the grid.

## Video: hosted or linked

- **Hosted** (`video_storage_path`) — the coach uploads a clip to a **private
  Supabase Storage bucket** `exercise-videos` (path `{tenant_id}/{file}`; staff-only
  upload, tenant-member read via storage RLS). It streams **inline** in-app via a
  short-lived **signed URL**.
- **Linked** (`video_url`) — an external URL (YouTube/Vimeo) opened in the browser.
- The daily loop reads the snapshot (`assignment_exercises.video_storage_path` /
  `video_url`), so hosted video plays inline in the session runner too.

## Data

<Callout>Tables: `exercises`, `tags`, `exercise_tags` (join). All carry `tenant_id`.</Callout>

**`exercises`**

| Column | Notes |
| --- | --- |
| `id` | uuid pk |
| `tenant_id` | tenant isolation |
| `owner_id` | the coach (person) who owns it |
| `name` | required |
| `description` | optional |
| `video_url` | link-based (v1 default) |
| `video_storage_path` | hosted video (private `exercise-videos` bucket) |
| `thumbnail_storage_path` | cover image (public `exercise-thumbnails` bucket); required by the app, nullable in DB for legacy rows |

**`tags`** are faceted by `category` (movement pattern · main muscle group ·
equipment · tempo, extensible), unique per `(tenant_id, category, label)`.
`exercise_tags` joins exercises ↔ tags.

## RLS

Tenant isolation is the first predicate on every policy. Within a tenant:

- **Read** — any staff member reads the whole tenant library.
- **Insert** — a new exercise is always owned by its creator (`owner_id = self`).
- **Update / delete** — the **creator** (`owner_id = self`) **or** the tenant
  **`owner`** role (`current_has_role('owner')`). So a coach manages only their
  own exercises, while the tenant owner can edit or delete **any** exercise. The
  `exercise_tags` write policy carries the same creator-or-owner rule so "edit any
  exercise" also covers its tag links.

See [Security & RLS](/docs/backend/security-and-rls).

## App

- `ExerciseRepository` (repository pattern; explicit column selects). Adds
  `uploadThumbnail` and `thumbnailPublicUrl` alongside the video helpers.
- `exercisesProvider` (per-coach), `exerciseTagsProvider`.
- Library screen: searchable / tag-filterable **2-column card grid** (thumbnail ·
  name · tags), with a grid loading skeleton.
- Editor: **required thumbnail picker** (16:9 tile, upload-on-pick with preview),
  video field, description, tag chip editor with **find-or-create** tags; delete.
  Video opens via `url_launcher`.
