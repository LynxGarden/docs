## The flow

1. Open app → the [Home tab](/docs/features/home-and-health) shows the **next
   session** card plus the full session menu (a check marks completed sessions,
   from `assignment_sessions.last_completed_at`) → pick one.
2. Enter a session → a **swipeable carousel**. Swiping cycles through the current
   exercise's **sets** first (a page-indicator row of **dots** under the exercise
   name shows which set you're on); once its sets are done, the next swipe moves to
   the **next exercise**. A synced top selector jumps between exercises, and tapping
   a dot jumps to that set. **Swiping away from a set auto-saves** any
   typed-but-unlogged input (silently — no toast, no auto-advance), and dismisses
   the keyboard.
3. Per set card (redesigned in CP6/CP7):
   - **Method banner** — when the exercise isn't a straight set, a full-width
     indicator at the very top of the card names the training method (and the
     exercise's position inside its group, e.g. `Superset · 1/2`).
   - **Top row** — a small thumbnail (top-left) + the exercise **title** and
     **subtitle** (target summary — formatted
     `4×12 · 60kg @ RPE 8 · Tempo: 3-1-0-1 · rest 120s`: volume parts first,
     then `@` before the RPE/RIR intensity, tempo with an explicit `Tempo:`
     prefix), and an info affordance opening the **exercise detail sheet**
     (description · video · a start/stop/reset **timer** · the client's
     **global notes** for that exercise · a 1–5 **difficulty rating**).
   - **See last time's actuals** ← the priority feature.
   - **Enter actuals** via the exercise's **config-driven metric form** (the fields
     the coach defined in `metric_schema`; falls back to reps/weight) + **Log set**
     (fills the dot and auto-advances); re-open a logged set to **edit** it.
   - **Rest timer** — when the prescription has a pause, the card shows
     `Rest: {n} s` with a **Start timer** button; the countdown runs **top-right
     in the nav bar** (tap to cancel, heavy haptic at zero), so it survives
     swiping between sets.
   - **Swap** the exercise (tag-driven suggestions from the same library).
4. Swipe past the last exercise → a **completion card** with a **1–10 session
   difficulty slider** (smiley feedback 😄 → 🥵, success→error accent);
   **Mark session complete** sends the rating as `p_rating` to
   `complete_session`. Until the backend accepts that parameter the app retries
   without it, so completion never fails on an older backend.

Online-only in v1 (clear banner when disconnected).

## "Last time" — first-class

Backed by a per-client, per-exercise history in **`logged_entries`**. When an
exercise renders we fetch the most recent prior entry for `(person_id,
exercise_id)` and show it beside today's inputs. The index below is load-bearing:

```sql
create index logged_entries_last_time_idx
  on public.logged_entries (person_id, exercise_id, logged_at desc);
```

### `logged_entries`

| Column | Notes |
| --- | --- |
| `tenant_id` | tenant isolation |
| `person_id` | whose history this is |
| `exercise_id` | for the "last time" lookup (kept stable across swaps) |
| `assignment_exercise_id` | the log's context (nullable) |
| `entry_type` | default `strength_set` (extensible) |
| `set_index`, `reps`, `weight`, `time_seconds` | legacy actuals (kept for last-time / review) |
| `data` | jsonb — the config-driven metric values, keyed by `metric_schema` field key |
| `logged_by` | who logged it (client, or staff on-behalf) |
| `logged_at` | timestamp; drives "last time" ordering |

## RLS

- **Client** reads/writes **their own** rows (`person_id = logged_by = me`).
- **Staff** read the tenant's clients' rows and may **log on behalf**
  (`logged_by = me`, any `person_id` in tenant).
- A client cannot log for another person, and cannot spoof `logged_by`.

## RPCs

Clients own their assignment but **cannot write `assignment_*` directly** (those
tables are staff-write only). So the two write actions in the runner go through
`SECURITY DEFINER` RPCs that authorise **owns-the-assignment OR staff**:

- **`complete_session(assignment_session, rating?)`** — stamps
  `last_completed_at = now()` and, when **`p_rating`** (the 1–10 session
  difficulty from the finish card) is sent, writes it to
  `assignment_sessions.last_rating` (migration `20261021120000_session_rating`
  in Lynx-backend). The app still falls back to the rating-less call, so
  completion never fails on an older backend.
- **`swap_assignment_exercise(assignment_exercise, new_exercise)`** — repoints the
  snapshot to a different library exercise, copies the new `name`/`video_url` into
  the snapshot, and records the original in `swapped_from_exercise_id` (kept stable
  across repeated swaps via `coalesce`), so `exercise_id`-keyed "last time" history
  stays uncorrupted.

## App (`features/training`)

- **Models** (`data/models/active_assignment.dart`) — `ActiveAssignment` →
  `TrainingAssignmentSession` → `TrainingExercise` (snapshot target + name/video +
  thumbnail path),
  and `LoggedEntry`. All read the `assignment_*` / `logged_entries` rows.
- **`TrainingRepository`** — `loadActiveAssignment`, `lastEntriesFor(exerciseId)`
  (groups the most-recent logging occasion), `logSet` (client logs own,
  `logged_by = self`; returns the entry id) and `updateSet` (edit an already-logged
  set — a direct `logged_entries` write, allowed under RLS since it's the client's
  own row), `completeSession`, `swapExercise` (last two via the RPCs).
- **Providers** — `activeAssignmentProvider` (the signed-in client's instance),
  `lastEntriesProvider(exerciseId)` (family). Invalidated after complete/swap.
  `activeAssignmentProvider` is a `StreamProvider`: it yields an initial REST
  snapshot, then subscribes to realtime changes on the client's `assignments`
  rows to auto-refresh when a coach (re)assigns a program. **Realtime is
  best-effort** — the subscription is wrapped so a websocket that can't connect
  (some networks, and reliably the iOS simulator) is swallowed rather than
  surfaced: the tab keeps serving the last good REST snapshot, and
  pull-to-refresh / invalidation still update it. It never falls into the
  "You're offline" error state just because realtime is unavailable.
- **Entry point** — the old Train tab was replaced by the
  [Home tab](/docs/features/home-and-health) (`features/home`), which hosts the
  next-session card and the session menu and pushes the runner.
- **Session runner** (`SessionRunnerScreen`) — a per-(exercise, set) `PageView` plus
  a trailing **completion** page, with a synced top exercise selector and a set-dots
  indicator. Each card has a **method banner** (when not a straight set), a compact
  **top row** (small thumbnail · title · target subtitle · detail affordance) and,
  below, the exercise's **config-driven metric form** (`MetricFormRenderer` over
  `metric_schema`; falls back to reps/weight), a **LAST TIME** block (values
  prefill per set), an optional **rest row** (`Rest: {n} s` + Start timer → nav-bar
  countdown), and a **Log set**/**Save** button. Logging writes the `values` map to
  `logged_entries.data` plus derived `reps`/`weight`/`time_seconds` for last-time +
  review. Swiping away from a set flushes unsaved input via a per-page save hook
  (also flushed before completing the session). Grouped
  (superset/MDS/contrast/ramp) exercises render as one block; interval methods
  (EMOM/E2MOM/E3MOM) surface an in-card timer. The **exercise detail sheet**
  (`showExerciseDetailSheet`) adds description · video · a stopwatch timer · global
  per-exercise notes (`exercise_notes`) · a 1–5 difficulty rating
  (`exercise_feedback`). The completion page carries the 1–10 smiley difficulty
  slider. Swap re-points the snapshot via the RPC.
