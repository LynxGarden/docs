## The flow

1. Open app → the assigned program shows as a **list of sessions** → a badge marks
   which was completed last (`assignment_sessions.last_completed_at`) → pick the next.
2. Enter a session → a **swipeable carousel**. Swiping cycles through the current
   exercise's **sets** first (a page-indicator row of **dots** under the exercise
   name shows which set you're on); once its sets are done, the next swipe moves to
   the **next exercise**. A synced top selector jumps between exercises, and tapping
   a dot jumps to that set.
3. Per set card:
   - **Thumbnail + video hero** at the top — the cover image, with a play badge
     that opens the inline video player when the exercise has a video.
   - **See the target** — the prescription snapshot.
   - **See last time's actuals** ← the priority feature.
   - **Enter actuals for that set** — reps / weight / time + **Log set** (fills the
     dot and auto-advances to the next set); re-open a logged set to **edit** it.
   - **Swap** the exercise (tag-driven suggestions from the same library).
4. Swipe past the last exercise → a **completion card**; **Mark session complete**
   there.

Online-only in v1 (clear banner when disconnected).

## "Last time" — first-class

Backed by a per-client, per-exercise history in **`logged_entries`**. When an
exercise renders we fetch the most recent prior entry for `(person_id,
exercise_id)` and show it beside today's inputs. The index below is load-bearing:

```sql
create index logged_entries_last_time_idx
  on public.logged_entries (person_id, exercise_id, logged_at desc);
```

### `logged_entries`

| Column | Notes |
| --- | --- |
| `tenant_id` | tenant isolation |
| `person_id` | whose history this is |
| `exercise_id` | for the "last time" lookup (kept stable across swaps) |
| `assignment_exercise_id` | the log's context (nullable) |
| `entry_type` | default `strength_set` (extensible) |
| `set_index`, `reps`, `weight`, `time_seconds` | actuals |
| `data` | jsonb — future entry types |
| `logged_by` | who logged it (client, or staff on-behalf) |
| `logged_at` | timestamp; drives "last time" ordering |

## RLS

- **Client** reads/writes **their own** rows (`person_id = logged_by = me`).
- **Staff** read the tenant's clients' rows and may **log on behalf**
  (`logged_by = me`, any `person_id` in tenant).
- A client cannot log for another person, and cannot spoof `logged_by`.

## RPCs

Clients own their assignment but **cannot write `assignment_*` directly** (those
tables are staff-write only). So the two write actions in the runner go through
`SECURITY DEFINER` RPCs that authorise **owns-the-assignment OR staff**:

- **`complete_session(assignment_session)`** — stamps `last_completed_at = now()`.
- **`swap_assignment_exercise(assignment_exercise, new_exercise)`** — repoints the
  snapshot to a different library exercise, copies the new `name`/`video_url` into
  the snapshot, and records the original in `swapped_from_exercise_id` (kept stable
  across repeated swaps via `coalesce`), so `exercise_id`-keyed "last time" history
  stays uncorrupted.

## App (`features/training`)

- **Models** (`data/models/active_assignment.dart`) — `ActiveAssignment` →
  `TrainingAssignmentSession` → `TrainingExercise` (snapshot target + name/video +
  thumbnail path),
  and `LoggedEntry`. All read the `assignment_*` / `logged_entries` rows.
- **`TrainingRepository`** — `loadActiveAssignment`, `lastEntriesFor(exerciseId)`
  (groups the most-recent logging occasion), `logSet` (client logs own,
  `logged_by = self`; returns the entry id) and `updateSet` (edit an already-logged
  set — a direct `logged_entries` write, allowed under RLS since it's the client's
  own row), `completeSession`, `swapExercise` (last two via the RPCs).
- **Providers** — `activeAssignmentProvider` (the signed-in client's instance),
  `lastEntriesProvider(exerciseId)` (family). Invalidated after complete/swap.
  `activeAssignmentProvider` is a `StreamProvider`: it yields an initial REST
  snapshot, then subscribes to realtime changes on the client's `assignments`
  rows to auto-refresh when a coach (re)assigns a program. **Realtime is
  best-effort** — the subscription is wrapped so a websocket that can't connect
  (some networks, and reliably the iOS simulator) is swallowed rather than
  surfaced: the tab keeps serving the last good REST snapshot, and
  pull-to-refresh / invalidation still update it. It never falls into the
  "You're offline" error state just because realtime is unavailable.
- **Train tab** (`TrainScreen`) — the program name + session menu; each session
  card shows its exercise count and a **Completed** badge (from `last_completed_at`);
  pull-to-refresh; empty/offline states. The loading state uses a Train-tailored
  skeleton (`SliverTrainSkeleton`) — a program-name header bar plus `AppCard`-shaped
  session placeholders — so the shape matches the loaded list and doesn't shift on
  the swap to real data.
- **Session runner** (`SessionRunnerScreen`) — the **exercise frame stays put while
  only the bottom set-input area slides**: the `PageView` drives just the bottom,
  whose pages are every **(exercise, set)** pair in order plus a trailing
  **completion** page, so swiping steps through a set at a time and rolls into the
  next exercise once the current one's sets are done. The static **top**
  (thumbnail/name/target/last-time) is rendered outside the pager and cross-fades
  only when the exercise changes. A synced **top selector** reflects the current
  exercise (one cell per exercise + a **Finish** cell, tap-to-jump), and a **dots
  page-indicator** under the name reflects the current set (elongated pill =
  current, filled = logged, muted = pending; tap a dot to jump to that set). The
  frame leads with a **thumbnail + video hero** (16:9 cover from the public
  `exercise-thumbnails` bucket via a direct URL; a play badge opens the video
  player sheet when a video exists), then name + **swap**, the **Target**, set-type
  & coach notes, a **LAST TIME** block, and numeric inputs (reps · weight · time)
  with a **Log set** button that logs that set and auto-advances; re-opening a
  logged set shows **Save** to edit it (`updateSet`). Last-time values prefill the
  inputs per set; state persists across swipes (`AutomaticKeepAlive` + a
  parent-held slot map keyed by `assignment_exercises.id`). The **completion**
  page's **Mark complete** button ends the session with a heavy-haptic success.
  Swap re-points the snapshot via the RPC. Legacy assignments made before
  thumbnails existed render a neutral placeholder.
